# 菜单栏、隐藏图标与恢复窗口

> 什么时候该读：**改、评审或排查菜单栏菜单、开机自启动、隐藏菜单栏图标、再次打开应用、轻量恢复主窗口，或把输入小窗误当成常驻入口前必读。** 不读会把点外面就关的输入面板当成恢复面，或在隐藏图标后留下找不到的后台应用。

跨产品完成态以全局 [macOS 应用开发：菜单栏、生命周期与后台服务](~/.config/agentsync/docs/MACOS_APP_DEVELOPMENT_GUIDE.md) 为准。本篇只写 OpenInput 已裁定的产品行为。

## 产品形态

OpenInput 是菜单栏常驻的附件应用（不出现在程序坞）。输入小窗是**唤出工具**：快捷键或菜单唤出，点外面关闭。它不是主窗口，也不是隐藏图标后的恢复面。禁止把输入小窗改成常驻、禁止拿它顶替「打开主窗口」。

允许隐藏菜单栏图标的前提：另有一个**轻量、带标题栏、点外面不会消失**的恢复主窗口。

## 菜单必备项

菜单栏图标可见时，菜单必须包含（英文为缺省文案）：

| 项 | 行为 |
|---|---|
| Open Main Window | 把恢复主窗口带到当前屏幕前方，可直接操作。 |
| Launch at Login | 展示系统真实状态；默认关闭。待系统批准时开关**不能显示成已开启**，并提供前往「系统设置 → 通用 → 登录项」的入口。 |
| Hide Menu Bar Icon | 立刻隐藏图标，**不弹任何窗口**。再次打开应用或点「打开主窗口」才出示恢复主窗口。 |
| Check for Updates… | 走现有 Sparkle 公开更新源，不得换成空按钮。 |
| Quit | 用户主动退出；系统因图标显隐顺手发出的退出必须拦住。 |

设置入口仍保留。输入小窗的「显示输入小窗」与恢复主窗口不是同一件事。

## 隐藏图标与再次打开

- 图标显示状态存在 `menuBar.iconVisible`。键不存在 = 显示。禁止把「键不存在」读成关闭。
- 隐藏后应用继续按原约定工作（热键、自动弹出、听写等不因图标消失而停）。
- 隐藏的同一时刻**禁止**出示恢复主窗口；只记下隐藏状态并撤掉图标。
- 从「应用程序」、Spotlight 或系统再次打开时：若图标已隐藏，必须把恢复主窗口带到前台。
- 图标已隐藏时的用户主动冷启动（非登录项），同样直接出示恢复主窗口。
- 用户从系统菜单栏移除本应用图标时：记下真实状态、拦住非用户退出；**不要**当场弹窗。

## 恢复主窗口

独立的小型带标题窗口，不是输入小窗，也不是把设置页七个页签直接当成唯一恢复面。至少提供：

- 应用仍在工作的说明
- Show Menu Bar Icon（打开后图标立刻出现）
- 开机自启动（真实三态；待批准不能显示成已开启）
- 检查更新
- 在图标隐藏时仍能退出、仍能打开完整设置

关掉恢复窗口不得退出应用。

## 开机自启动

- 签名安装包的主路径走 MacKit 的登录项封装（系统三态：开 / 关 / 待批准）。待批准 ≠ 已开启。
- ad-hoc / Debug 构建才允许本应用内的 LaunchAgent 回退；**禁止**把 LaunchAgent 默认进公共库。
- 绝不能在后台自动重装 LaunchAgent，否则会孵出卡住的程序坞图标。
- 本应用有公开更新源，检查更新继续用现有 Sparkle，不要接 MacKit 的更新单元。

## Mac 真机验收（Linux 开发机无法代跑）

1. 图标可见：菜单有打开主窗口、开机自启动、隐藏图标、检查更新、退出；点开主窗口是带标题的恢复窗，不是输入小窗。
2. 关闭开机自启动后重新登录：不启动。开启后重新登录：会启动。系统待批准时：开关不是「开」，并能进登录项。
3. 隐藏图标：输入小窗热键仍可用；**当下不弹恢复窗**；之后从「应用程序」再打开或点「打开主窗口」才出示恢复窗，其中「显示菜单栏图标」打开后图标立刻回来。
4. 图标隐藏时从「应用程序」或 Spotlight 再打开：恢复窗口到前台。登录项拉起时即使图标已隐藏也不弹窗。
5. 关掉恢复窗口：应用不退出。用户点退出后才退出。
6. 有更新 / 已是最新 / 断网三种检查更新结果与公开更新源一致。
